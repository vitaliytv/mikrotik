## Огляд

Створює сховище журналу запитів агента як окремий вузол для збереження подій у спільній директорії, щоб відокремити аудит від основного стану застосунку. Функція `createNodeJournalStore` працює fail-safe і не передає винятки назовні, тож збій під час роботи не перериває виклик для споживача.

## Поведінка

1. `createNodeJournalStore` визначає сховище журналу запитів агента в одному спільному місці для цього застосунку, з можливістю підміни директорії через `AGENT_REQUESTS_DIR`.
2. `createNodeJournalStore` створює записи як окремі JSON-файли з унікальним ідентифікатором, часовими мітками, статусом очікування, полями для повідомлень, дій, підсумку, питання, помилки, потреби в підтвердженні та зв’язку з батьківським записом.
3. `createNodeJournalStore` дає змогу зберегти новий запит агента як окрему подію аудиту, не змішуючи її з основним станом застосунку.
4. `createNodeJournalStore` уміє прочитати один запис за ідентифікатором і повернути його в поточному вигляді.
5. `createNodeJournalStore` уміє оновити вже наявний запис, зберігаючи нові дані та автоматично фіксуючи час останньої зміни.
6. `createNodeJournalStore` уміє перелічити всі доступні JSON-записи в директорії журналу та пропускає непридатні для читання або частково записані файли, щоб не зупиняти роботу всього сховища.
7. `createNodeJournalStore` працює fail-safe: помилки читання окремих записів не виходять назовні як фатальний збій для всього переліку.

## Гарантії поведінки

- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
