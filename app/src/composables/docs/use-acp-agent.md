## Огляд

`useAcpAgent` надає read-only доступ до вбудованого ACP-агента, щоб застосунок міг безпечно працювати з агентською інтеграцією без змін у файлах чи БД. Код спирається на `settings.json`. Помилки перехоплюються fail-safe і не кидаються назовні.

## Поведінка

1. `useAcpAgent` створює шлюз до вбудованого ACP-агента для read-only WAN-monitor сценаріїв, де відповіді агента спираються на доменні інструменти застосунку, а не на зміну файлів чи бази даних.

2. `useAcpAgent` задає безпечну робочу директорію для запуску агентів: у реальному застосунку використовує домашню теку користувача, а поза Tauri-середовищем переходить на нейтральне значення, щоб preview або недоступна системна тека не ламали завантаження модуля.

3. `useAcpAgent` підключає доступні ACP-провайдери для діалогу з агентом і вибору рівня моделі там, де це підтримується конкретним провайдером.

4. `useAcpAgent` для Pi-агента покладається на його власний конфіг `settings.json`, тому модель і provider визначаються конфігурацією Pi, а не перемикачем рівня всередині застосунку.

5. `useAcpAgent` повертає готовий in-app gateway для завантаження середовища, надсилання запитів, отримання відповідей, перегляду журналу та підтвердження дій агента.

6. `useAcpAgent` працює fail-safe: очікувані проблеми з оточенням не мають викидати винятки назовні й не повинні зупиняти весь інтерфейс застосунку.

## Гарантії поведінки

- Read-only: не виконує операцій запису (ФС/БД).
- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
