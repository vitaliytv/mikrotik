## Огляд

Модуль надає `ApiRos`, `connect`, `login` і `talk` для роботи з RouterOS API та `Config`, `home_path`, `load_config`, `connect_and_login`, `read_traffic` для доступу до конфігурації й поточних показників. Він звертається до мережі, але залишається fail-safe: не кидає винятків назовні й у разі недоступних даних або помилки може повертати порожнє значення замість винятку. Конфігурацію бере з оточення або з `~/.mikrotik.env`.

## Поведінка

- ApiRos — тримає з’єднання з RouterOS API для обміну командами та відповідями.
- connect — встановлює TCP-з’єднання з RouterOS API на вказаному хості.
- login — виконує двоетапний login до RouterOS API і повертає, чи він успішний.
- talk — надсилає команду в RouterOS API та збирає всі отримані репліки й атрибути до завершення обміну.
- Config — зберігає конфігурацію підключення: host, user і pass.
- home_path — будує шлях у домашньому каталозі для заданого імені.
- load_config — читає конфігурацію підключення з env-змінних або ~/.mikrotik.env, а для пароля вимагає явного значення.
- connect_and_login — завантажує конфіг, підключається до RouterOS API і виконує login; у разі помилки повертає повідомлення без panic.
- read_traffic — зчитує миттєві показники traffic для двох WAN-інтерфейсів і повертає значення окремо для rx/tx; якщо даних немає або сталася помилка запиту, для відповідних значень повертає порожні поля.

## Публічний API

- ApiRos: відображає доступ до RouterOS API й тримає під контролем з’єднання з роутером.
- connect: відкриває мережевий канал до RouterOS.
- login: входить у сесію RouterOS під заданими обліковими даними.
- talk: надсилає команду в RouterOS і повертає відповідь.
- Config: зберігає налаштування доступу до роутера й шлях до файлу конфігурації.
- home_path: формує шлях до домашньої теки користувача для пошуку конфігурації.
- load_config: читає конфігурацію з файла і збирає готові параметри підключення.
- connect_and_login: послідовно встановлює зв’язок із RouterOS і виконує вхід.
- read_traffic: миттєво зчитує швидкість прийому та передачі для обох WAN-ліній: zte_rx, zte_tx, soyea_rx, soyea_tx.

## Гарантії поведінки

- Read-only: не виконує операцій запису (ФС/БД).
- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
- За певних помилок повертає порожнє значення (напр. `null`) замість винятку.
