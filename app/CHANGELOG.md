# Changelog

## [0.6.4] - 2026-09-07

### Changed

- feat: show per-WAN CAKE upload telemetry

## [0.6.3] - 2026-09-02

### Changed

- Пом’якшено quality failover: severe і soft деградації мають окремі streak, перевагу candidate та hold-down; нові лічильники видно в Decision metrics.

## [0.6.2] - 2026-08-25

### Changed

- Сторінка перемикань показує надійну disk-історію на реальній часовій шкалі та підсумовує час роботи LMT і BITE за 24 години або 7 днів.

## [0.6.1] - 2026-08-24

### Fixed

- Додано синхронні хвилинні decision metrics обох WAN у дискову історію та MyMikroTik; failover переведено на source-routed ICMP/TCP probes без хибного ping interface.

## [0.6.0] - 2026-08-21

### Added

- Додано планові ICMP, TCP і DNS вимірювання обох upstream resolver та пасивні interface counters для LMT і BITE з chunked disk-історією RouterOS, нормалізацією ICMP loss/timeout і візуалізацією у вкладці «Якість».

## [0.5.10] - 2026-08-17

### Changed

- release: mymikrotik@0.5.9

## [0.5.9] - 2026-08-17

### Fixed

- Уніфіковано симетричний DUALWAN-health без LMT-primary режиму та повторних подій перемикання.

## [0.5.8] - 2026-08-13

### Changed

- Додано запуск і відображення router-side тесту швидкості LMT та BITE.

## [0.5.7] - 2026-07-23

### Fixed

- Sticky scheduler тепер визначає активний WAN лише за DHCP main-route priority, а не через нестабільну global-змінну dwState. Ручне перемикання та UI завжди використовують той самий фактичний стан маршрутизації.

## [0.5.6] - 2026-07-23

### Changed

- Спрощено dual-WAN екран: залишено timeline active WAN і трафік інтерфейсів, прибрано дубльований погодинний графік перемикань, застарілі quality-графіки та probes. Аварійну фіксацію BITE перенесено в окреме меню.

## [0.5.5] - 2026-07-23

### Fixed

- Примусове перемикання WAN тепер підтверджує фактичний RouterOS state перед повідомленням про успіх. Кнопка наступного WAN визначається за активним main-маршрутом, тому після переходу на BITE показує LMT.

## [0.5.4] - 2026-07-23

### Added

- Sticky dual-WAN failover: primary WAN перемикається на резервний після трьох невдалих циклів без автоматичного повернення, з ручним переходом на конкретно вказаний наступний WAN.

Додано timeline-графік періодів, коли active WAN був LMT або BITE, та автоматичні повторні підключення до RouterOS кожні 5 секунд, коли API недоступний.

## [0.5.3] - 2026-07-22

### Fixed

- Технічний реліз для перевірки живого потоку автооновлення (0.5.2 → 0.5.3) після фіксу Quasar Dialog, функціональних змін немає

## [0.5.2] - 2026-07-21

### Fixed

- Зареєстровано Quasar Dialog у main.js — автооновлювач мовчки падав при спробі показати діалог "Доступне оновлення" (useUpdater() викликає $q.dialog, а був зареєстрований лише Notify), тож оновлення до 0.5.1 ніколи не пропонувалось користувачу

## [0.5.1] - 2026-07-21

### Changed

- Оновлено @7n/tauri-components до 0.13.9 — AgentDialog: лейбл моделі, видимість tier-селектора, продовження розмови при зміні агента, усунення гонки acp_spawn_agent/acp_prompt, коректна самоідентифікація моделі; fix(ci): changelog-release n-cursor замість стороннього @nitra/cursor

## [0.5.0] - 2026-07-20

### Added

- Кнопка "Відновити авто-перемикання" в діагностичному режимі — реверсує "Зафіксувати BITE": відновлює стандартні route-priority та знову вмикає DUALWAN-health scheduler. Раніше відновлення після ручної фіксації BITE вимагало ручних команд у RouterOS-терміналі.

## [0.4.2] - 2026-07-18

### Added

- Увімкнено devtools у зібраному застосунку (Cargo `tauri` feature) — тепер правий клік → Inspect Element відкриває справжній Web Inspector (консоль, мережа) навіть у релізній збірці, щоб можна було діагностувати такі речі як тиху помилку перевірки оновлення.

## [0.4.1] - 2026-07-17

### Fixed

- Технічний реліз для перевірки живого потоку автооновлення (0.4.0 → 0.4.1), функціональних змін немає

## [0.4.0] - 2026-07-17

### Added

## [0.3.1] - 2026-07-16
